# 枝と HEAD

「ブランチを切る」という言い方のせいで、枝を切ると**何かがコピーされる**と思われがちです。
実際には、何もコピーされません。

ブランチは、**あるコミットに付けた名前**でしかありません。

```bash
git branch feature       # いまのコミットに feature という名前を付ける
```

これだけです。コミットは 1 つも増えず、ファイルも動きません。
増えたのは「feature」という 1 つの名札だけです。

## HEAD は別のポインタです

名札がもう 1 つあります。`HEAD` です。これは「**いま自分がどこにいるか**」を指します。

```bash
git switch feature       # HEAD を feature へ移す
```

ここでも、コミットは増えません。`HEAD` の指す先が変わっただけです。

つまり、枝を切って移るという操作は、**付箋を 1 枚貼って、もう 1 枚を貼り替える**ことに等しいわけです。

## 動くのはコミットしたときです

では、いつ枝が伸びるのか。コミットしたときです。

```bash
git switch -c feature    # 作って移る（branch と switch を一度に）
git commit -m "枝の上で作業"
```

このとき Git は 2 つのことをします。

1. 新しいコミットを 1 つ作る
2. **HEAD が指している枝**を、そのコミットへ動かす

`main` は動きません。`HEAD` が `main` を指していないからです。
「枝が伸びる」の正体は、この 2 番目です。

## 分かれるのは 2 コミット目からです

枝を切った直後に 1 回コミットしても、履歴はまだ分かれていません。

```
main ── (A) ── (B) ← feature, HEAD
```

`main` は B の**祖先**を指しているだけで、1 本の道の途中にいます。
このサイトのグラフは行を分けて描くので枝分かれに見えますが、実態はまだ 1 本です。

`main` 側にもコミットして初めて、「どちらにも相手の持たないコミットがある」状態になります。
ここから先が、本当の意味で分かれた履歴です。

```
        (C) ← main
       /
── (A) ── (B) ← feature
```

この違いは、あとで merge を学ぶときに効いてきます。
分かれていなければ fast-forward、分かれていれば 3-way。決めているのはこの形だけです。

## 最初のコミットまで main は存在しません

`git init` した直後、`main` という枝は**まだありません**。

`HEAD` は「これから作られる main」を指していて、最初の `commit` がその枝を生みます。
本物の Git と同じ挙動で、unborn HEAD と呼ばれます。

`git status` を打つと「まだコミットがありません」と出るのはこのためです。
名前を付ける相手（コミット）がまだ無いので、枝も作りようがない、というだけの話です。

## 動かない名札もあります ― tag

枝とほとんど同じものが、もう 1 つあります。**タグ**です。

```bash
git tag v1.0             # いまのコミットに v1.0 という名前を付ける
git tag v0.9 HEAD~1      # 1 つ前のコミットに付ける（id を直接書いてもよい）
git tag                  # 一覧
git tag -d v0.9          # 外す
```

やっていることは `git branch` と変わりません。コミットに名前を貼るだけです。
違いは 1 つだけ ― **タグは動きません**。

```bash
git tag v1.0
git commit -m "続きの作業"
```

このあと `main` は新しいコミットへ進みますが、`v1.0` は貼った場所に残ったままです。
`HEAD` が指しているのは枝であって、タグではないからです。

だから使い分けはこうなります。

| 名札 | 何に付ける名前か |
| --- | --- |
| 枝 | **これから伸びていく**流れに付ける名前 |
| タグ | **この時点のもの**と言いたいときに付ける名前 |

実務でいちばん多い用途はリリースの目印です。「v1.2.0 として世に出したのはこのコミット」を
あとから確実に指せるようにしておく、という使い方をします。

### タグと枝は、別の入れ物です

同じ名前のタグと枝を、両方作れます。Git の中で住んでいる場所が違うからです。

| どちらか | どこに置かれるか |
| --- | --- |
| 枝 | `refs/heads/v1.0` |
| タグ | `refs/tags/v1.0` |

ただし、作れることと使いやすいことは別です。
`git switch v1.0` と打ったとき、Git はどちらの話か決められません。
本物は警告を出したうえで**枝のほう**を選びます。

```bash
git tag v1.0
git branch v1.0     # 作れてしまう
git switch v1.0     # 枝のほうへ移る（本物は警告も出す）
```

作れるからといって、そうする理由はありません。名前は分けておくのが無難です。
