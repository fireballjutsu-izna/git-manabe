# detached HEAD

`detached HEAD` は、Git でいちばん怖がられている言葉かもしれません。
「切り離された」という響きが、壊れたように聞こえます。

壊れていません。**HEAD が枝ではなくコミットを直に指している**、それだけの状態です。

## 2 つのモード

`HEAD` の指し方には 2 通りあります。

| モード | HEAD が指すもの | コミットすると |
| --- | --- | --- |
| ふつう | 枝の名前（`main` など） | その枝ごと前へ進む |
| detached | コミットそのもの | HEAD だけが進み、**どの枝も動かない** |

```bash
git checkout a1b2c3d     # コミットを直に指す → detached
git switch main          # 枝に戻る
```

`switch` は枝にしか移れません。コミットを直に指したいときは `checkout` を使うか、
`git switch --detach <commit>` と明示します。区別があるのは、
うっかり detached に入らないようにするためです。

## ここでのコミットが行方不明になる理由

detached HEAD でコミットすると、こうなります。

```
── (A) ── (B) ← main
        \
         (C) ← HEAD
```

`C` を指している名前が、`HEAD` しかありません。
この状態で `git switch main` を打つと、`HEAD` は `main` へ移ります。

```
── (A) ── (B) ← main, HEAD
        \
         (C)     ← 誰も指していない
```

`C` は**消えていません**。ただ、指す名前が 1 つも無くなりました。
どこからも辿れないので、`git log` にも出てきません。これが「行方不明」の正体です。

このサイトでは、そういうコミットを**破線・薄い色**で描き続けます。
消えていないことを見せたいからです。

## 拾い方

名前を付ければ戻ってきます。

```bash
git switch -c 救出 a1b2c3d    # そのコミットに枝を生やす
```

id が分からなくなっていても大丈夫です。`git reflog` に、HEAD が通ってきた道が全部残っています。
そちらは[別の記事](/docs/reflog)で扱います。

## わざと使う場面もあります

detached HEAD は事故だけのものではありません。

- 過去のコミットの状態を見てみたい
- そのコミットでテストを走らせたい
- どのコミットから壊れたかを二分探索する（`git bisect` が内部でこれをやります）

いずれも「見に行くだけで、枝は動かしたくない」場面です。
そのためのモードだと思えば、名前ほど怖いものではありません。
