# .gitignore と、出してしまった秘密

`.gitignore` でいちばん多い詰まり方は、これです。

> `.gitignore` に書いたのに、まだ `git status` に出てくる。

書き方が間違っているのではありません。**もう追跡しているから**です。

## .gitignore が効く相手は 1 種類だけ

`.gitignore` が効くのは、**まだ一度もコミットされていないファイル**だけです。

| ファイルの状態 | `.gitignore` に書くと |
| --- | --- |
| まだ一度もコミットしていない | 無視される。`git add .` でも入らない |
| すでにコミット済み | **何も起きない**。これまでどおり追跡され続ける |

理由は Git の側から見ると単純です。
`.gitignore` は「これから見つけるファイルのうち、拾わなくていいもの」のリストであって、
**すでに手元に持っているものを手放す**指示ではありません。

手放すには、別のコマンドが要ります。

## 追跡をやめる — git rm --cached

```bash
git rm --cached .env     # 追跡から外す。ファイルは手元に残る
git rm .env              # 追跡から外し、ファイルも消す
```

ほぼ常に `--cached` のほうです。
`.env` は手元では使い続けるので、消えては困ります。

外したあと、`.gitignore` に書いてあれば、そこからは無視されます。
**順番はどちらでも構いません**が、両方やらないと止まりません。

```bash
touch .gitignore
append .gitignore .env      # ← 無視すると決める
git rm --cached .env        # ← 追跡をやめる
git add .gitignore
git commit -m ".env を追跡から外した"
```

## 書き方

このサイトが読むのは 3 つだけです（実務ではこれで大半が足ります）。

```
# コメント。空行と # の行は読み飛ばされます
.env            名前がそのまま一致
*.key           拡張子で一致
secrets/        そのディレクトリの下ぜんぶ
```

本物にはもっと広い書式があります（`!` で打ち消す、途中の `/`、`**` など）。
考え方は同じで、**上から順に当てて、当たったら無視する**だけです。

## いちばん大事なところ — 履歴からは消えません

`git rm --cached` と `commit` で消えるのは、**これ以降のコミット**からだけです。

```bash
git rm --cached .env
git commit -m ".env を外した"

git diff HEAD~1 HEAD     # ← .env が消えた差分が見える
git show HEAD~1          # ← 1 つ前のコミットには、まだ中身が入っている
```

コミットは積み重ねであって、上書きではありません。
過去のコミットは書き換わっていないので、**中身はまだそこにあります**。

さらに、すでに `push` してしまっていれば、向こうにも残っています。
誰かが `clone` していれば、その人の手元にも残っています。

### だから、まずやることは「作り直す」です

履歴から本当に消す方法（`git filter-repo` など）はあります。
ですが、それは**全員の履歴を書き換える**操作で、共有済みなら全員の手元に影響します。
そして、消し終わるまでのあいだ、その値は漏れたままです。

順番はこうです。

1. **その値を無効にして、作り直す**（API キーの再発行、パスワードの変更）
2. `.gitignore` に足して、`git rm --cached` で追跡から外す
3. 履歴の書き換えが要るかは、そのあとチームで決める

1 が済んでいれば、履歴に残っている値はただの古い文字列です。
順番を逆にすると、掃除している最中もずっと有効なままになります。

## それでも入れたいとき

無視されているファイルを、意図して追跡することもできます。

```bash
git add -f config.local.json
```

`-f` が要るのは、**たいていは間違いだから**です。
本当に必要なときだけ使ってください。
