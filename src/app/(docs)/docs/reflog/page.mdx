# reflog ― やらかしから戻る

ここまでで、コミットをどこからも辿れなくする方法が 3 つ出てきました。

- [`reset --hard`](/docs/reset-modes) … 枝を後ろへ動かす
- [`rebase`](/docs/rebase) … コミットを作り直す
- [detached HEAD](/docs/detached) でのコミット … 名前を付けずに置いていく

どれも**コミットを消してはいません**。指す名前が無くなっただけで、実体はそこにあります。

その実体に届く最後の道が `git reflog` です。

## HEAD が通ってきた道

```bash
git reset --hard HEAD~1        # しまった、1 つ消してしまった
git reflog                     # HEAD が通ってきた道が、新しい順に出る
```

```
b1c2d3e HEAD@{0}: reset --hard: HEAD~1 へ戻す
a9f8e7d HEAD@{1}: commit: 三つ目          ← いま辿れません
b1c2d3e HEAD@{2}: commit: 二つ目
```

`a9f8e7d` が、失くしたコミットです。**id さえ分かれば拾えます。**

```bash
git reset --hard a9f8e7d        # そこまで丸ごと戻す
git switch -c 救出 a9f8e7d      # いまの場所は残したまま、枝を生やして拾う
```

後者のほうが安全です。いまの状態を壊さずに済みます。

## `HEAD@{1}` と `HEAD~1` は別物です

紛らわしいのですが、意味がまったく違います。

| 書き方 | 何をさかのぼるか | 行き先 |
| --- | --- | --- |
| `HEAD~1` | **履歴**（親） | いまのコミットの親 |
| `HEAD@{1}` | **時間**（reflog） | 1 つ前に HEAD がいた場所 |

`reset --hard HEAD~1` を実行したあとだと、
`HEAD~1` は「戻った先のさらに親」を指し、
`HEAD@{1}` は「reset する前にいた場所」＝ 失くしたコミットを指します。

同じ「1 つ前」でも、辿る軸が違うわけです。

## あなたの手元にしかありません

枝やタグと違い、reflog は**共有されません**。

- 他の人の reflog は見られません
- 自分の reflog も push されません
- クローンし直すと、そこには何も無いところから始まります

**自分の操作の記録**だから、自分がやらかしたことだけを救ってくれます。

## 期限があります

reflog のエントリは永久には残りません。既定では、
辿れるものが 90 日、辿れないものが 30 日で掃除されます。

「1 年前に消したコミット」は、もう戻せないかもしれません。
気づいたら早めに拾ってください。

## それでも戻せないもの

`--hard` で消した**作業中の変更**（コミットしていなかったもの）は、reflog にも残りません。

reflog は「HEAD が通ってきた道」の記録なので、
そもそもコミットになっていないものは記録されようがないのです。

こちらは本当に戻せません。`--hard` の前に一呼吸おくか、
[stash](/docs/stash) に逃がしてから打つのが安全です。
