# リモート ― fetch と pull

リモートは、**別の場所にあるもう 1 つのリポジトリ**です。

ここがいちばん大事な点で、**向こうのコミットは、fetch するまであなたのグラフに存在しません**。
見えていないのではなく、まだ持っていません。

```bash
git remote add origin <url>   # 名前を付けるだけ。まだ通信していない
git push origin main          # 送る
```

このサイトには `teammate 2` という独自コマンドがあります。
「誰かが向こうへ 2 つコミットした」ことにするものです。

打っても、**グラフは 1 ミリも動きません**。持っていないからです。
右のリモートパネルだけが「向こうに、まだ持っていないコミットがあります」と教えてくれます。

## fetch と pull の違いは 1 つだけ

```bash
git fetch origin              # 取ってくるだけ
git pull origin main          # 取ってきて、取り込む
```

`fetch` のあと、グラフには新しいコミットが現れ、`origin/main` はそこへ移ります。
**でも `main` は動きません。**

これが fetch です。取ってくるだけで、合流はしません。
自分の作業を壊す心配がないので、いつ打っても安全なコマンドです。

`pull` は、その fetch のあとに `git merge origin/main` を続けて実行します。それだけです。
今度は `main` も動きます。

> `pull` ＝ `fetch` ＋ `merge`

分けて打つ癖をつけると、「取ってきたものを見てから取り込む」ができるようになります。

## origin/main は「最後に見たとき」の記録

`origin/main` は**リモート追跡ブランチ**と呼ばれます。
「最後に fetch / push したとき、向こうの `main` がどこを指していたか」を覚えているだけの名札です。

自分では動きません。あなたが `fetch` するまで古いままです。

**その古さが、そのまま「pull を忘れている」状態です。**
リモートパネルの「進み / 遅れ」は、この名札と自分の枝を比べた数です。

## push が断られるとき

```
origin の main には、あなたが持っていないコミットがあります。
先に git pull origin main で取り込んでから、送り直してください。
```

push でいちばん出会うエラーですが、意味はこれだけです。

**向こうに、こちらの知らないコミットがある。**

Git は「早送りにならない push」を既定で断ります。
そのまま通すと、向こうにあるコミットが履歴から外れてしまうからです。

直し方も 1 つで、先に取り込んでから送ります。

## force push について

`--force` を付けると、この安全装置を外せます。
向こうの履歴を、こちらの履歴で上書きします。

他の人が持っているコミットが消えるので、共有された枝には使わないでください。
どうしても必要なときは `--force-with-lease` のほうが安全です。
「自分が最後に見たときから向こうが変わっていなければ」という条件が付きます。

## 送ってしまった秘密 ― 残る場所が増えます

[.gitignore の記事](/docs/ignore)で、秘密の値をコミットしてしまったときの話を途中まで書きました。
`git rm --cached` してコミットしても、**1 つ前のコミットには残っている**、というところまでです。

リモートまで来ると、残る場所が増えます。

| どこ | 秘密の値は |
| --- | --- |
| 自分の手元の履歴 | 残っている |
| `push` してあるリモート | 残っている |
| そこから取っていった人の手元 | 残っている |

理由は、この記事のいちばん最初と同じ話です。
リモートは**別のリポジトリ**で、`push` はそこへコミットを丸ごと配る操作でした。
配ったあとで中身だけ引っ込める、という道は用意されていません。
`fetch` した人の手元にあるのも、同じコミットの完全な複製です。

（本物の Git では、`git clone` した人の手元にも同じものが揃います。
このサイトに `clone` は入っていませんが、`fetch` で取ってくるのと持ち物は変わりません。）

### revert では消えません

[revert](/docs/revert) は打ち消しを**足す**コマンドです。
ファイルの中身は元どおりになりますが、秘密の値が入ったコミットはそのまま履歴に残ります。
「消した」という記録が 1 つ増えるだけです。

### 本当に消すなら、全員を巻き込みます

履歴から取り除く道具はあります（`git filter-repo`、古くは `git filter-branch`）。
このサイトでは扱っていませんが、やっていることは[対話的 rebase](/docs/interactive) と同じ向きで、
**そのコミットから先を全部作り直す**操作です。id が変わるので、こうなります。

| 誰が | 何をすることになるか |
| --- | --- |
| 作業した人 | 書き換えた履歴を `--force-with-lease` で押し出す |
| すでに取ってきた人 | 全員、手元の枝を作り直す |
| 気づかず `pull` した人 | 手元の古い履歴が混ざって、消したはずのコミットが戻る |

そして、この段取りをしているあいだじゅう、その値は有効なまま残っています。

だから順番は、`.gitignore` の記事に書いたとおりです。

1. **その値を無効にして、作り直す**（キーの再発行、パスワードの変更）
2. `.gitignore` に足して、`git rm --cached` で追跡から外す
3. 履歴を書き換えるかどうかは、そのあとチームで決める

1 が済んでいれば、履歴のあちこちに残っているのは、ただの古い文字列です。
順番を逆にすると、全員の手元を作り直しているあいだも、鍵は開いたままになります。

## このサイトでの簡略化

リモートは同じブラウザの中の別の入れ物で、実際の通信はしていません。
それでも、**手元と向こうが別のリポジトリである**という関係はそのまま再現しています。
fetch するまでコミットが存在しないのも、そのためです。
