# reset の 3 つのモード

`git reset` は、`--soft` / `--mixed` / `--hard` という 3 つの顔を持ちます。
名前を共有している**3 つの別コマンド**だと思うのが、いちばん早いです。

```bash
git reset --soft  HEAD~1   # 枝だけ戻す
git reset --mixed HEAD~1   # 枝を戻し、ステージも空にする（既定）
git reset --hard  HEAD~1   # 枝を戻し、ステージも作業ディレクトリも空にする
```

## 枝の動きは全部同じです

ここが要点です。**どのモードでも枝は同じだけ動きます。**

違うのは、取り消したコミットに入っていた変更を[どの領域](/docs/areas)まで戻すか、それだけです。

| モード | 枝 (HEAD) | ステージ | 作業ディレクトリ | 取り消した変更は |
| --- | --- | --- | --- | --- |
| `--soft` | 動く | 残す | 残す | ステージに積まれたまま |
| `--mixed` | 動く | 消す | 残す | 未ステージの変更に落ちる |
| `--hard` | 動く | 消す | 消す（※） | 消える |

※ ただし **Git がまだ知らないファイル（untracked）は残ります。**
`--hard` が戻すのは Git が知っているものだけで、一度も `add` していないファイルには手が届きません。
消すには `git clean` という別のコマンドが要ります（このサイトには入っていません）。
「`--hard` したのに直らない」の多くは、これが原因です。

表を読むより、サンドボックスで 3 回打ち分けて**3 領域パネルのどこが光るか**を見るのが早いです。
`--soft` ではステージだけ、`--mixed` と `--hard` では両方が光ります。

## それぞれの使いどころ

**`--soft`** — 直前のコミットをやり直したいとき。
中身はステージに残っているので、そのまま `git commit -m "書き直したメッセージ"` で積み直せます。

**`--mixed`（既定）** — コミットの分け方を変えたいとき。
変更が未ステージに落ちるので、`add` し直して 2 つのコミットに分ける、といったことができます。

**`--hard`** — 全部無かったことにしたいとき。
いちばん危険です。あとで触れます。

## コミットは消えていません

`reset` は「削除」ではありません。**枝を後ろへ動かしているだけ**です。

```
── (A) ── (B) ── (C) ← main
```

ここで `git reset --hard HEAD~1` を打つと、

```
── (A) ── (B) ← main
            \
             (C)     ← 誰も指していない
```

`C` はそこにあります。指す名前が無くなっただけです。
[reflog](/docs/reflog) から拾い直せます。

## 戻せないものが 1 つだけあります

`--hard` で消した**作業中の変更**（コミットしていなかったもの）は、本当に戻せません。

reflog は「HEAD が通ってきた道」の記録なので、コミットになっていないものは載りません。
`--hard` を打つ前に、消えて困る変更が手元に無いかを確かめてください。

避けたいなら [stash](/docs/stash) に逃がしてから打つ、という手もあります。

## HEAD~1 の読み方

`HEAD~1` は「いまの場所から 1 代さかのぼる」という意味で、`HEAD^` と同じです。
`HEAD~2` なら 2 代。

コミットの id を直に書いても構いません。`git reset --hard a1b2c3d` は、
「main を a1b2c3d のところまで戻す」という意味になります。

## 共有した履歴には使えません

`reset` は履歴そのものを動かします。
すでに push して他の人が持っている履歴に使うと、向こうの履歴と食い違います。

共有済みのコミットを取り消したいときは、[revert](/docs/revert) を使ってください。
