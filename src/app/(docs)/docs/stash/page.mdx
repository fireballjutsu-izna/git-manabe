# stash ― 脇へどける

作業の途中で、別のことをしなければならなくなる。よくあります。

- 急ぎの修正を先に入れたい
- 別の枝の様子を見たい
- そもそも今の変更は、まだコミットしたくない

中途半端な状態でコミットしたくはない。かといって捨てたくもない。
そういうときに使うのが `stash` です。

```bash
git stash               # 作業ディレクトリとステージを空にして、脇へ
git stash list          # 何を退避しているか
git stash pop           # 戻す（退避の一覧からは消える）
git stash apply         # 戻す（一覧には残す）
git stash drop          # 捨てる
```

## 履歴に跡が残りません

`stash` の特徴はここです。**コミットを 1 つも作りません。**

動くのは[3 領域](/docs/areas)だけ。作業ディレクトリとステージが空になり、
その中身が「退避した箱」へ移ります。グラフは 1 ミリも変わりません。

`add` や `touch` もグラフを変えませんが、あれは 3 領域の中で動かしているだけです。
`stash` は**コミットを作らずに 3 領域を空にできる**唯一のコマンドで、
どけた中身は履歴の外の「箱」に入ります。

退避中は 3 領域パネルの下に一覧が出ます。コミットではないので、グラフには現れません。

## pop と apply の違い

どちらも「戻す」ですが、退避の一覧をどうするかが違います。

| コマンド | 中身は | 一覧からは |
| --- | --- | --- |
| `pop` | 戻る | **消える** |
| `apply` | 戻る | 残る |

同じ変更を複数の枝に当てたいときは `apply`。
ふつうに作業を再開したいだけなら `pop` です。

## 積み重なります

`stash` は何度でもできます。新しいものが `stash@{0}` になり、古いものが後ろへずれます。

```
stash@{0}: WIP on main   ← いちばん新しい
stash@{1}: WIP on main
```

引数なしの `pop` は `stash@{0}` を戻します。
溜めすぎると「どれが何だったか」が分からなくなるので、早めに戻すか捨てるのが無難です。

## 忘れられやすいコマンドです

`stash` の実際の困りごとは、使い方ではなく**存在を忘れること**です。

退避したまま別の作業に入り、数日後に「あの修正どこへやったか」となる。
グラフに出ないので、思い出す手がかりが少ないのが理由でもあります。

`git stash list` を時々見る習慣があると安心です。

## 本物の Git との違い

本物の `stash` は、内部では実はコミットを作っています。
どこの枝からも辿れない特殊なコミットとして保存し、`refs/stash` から指しています。

なので `git stash` した内容も、実は reflog から拾えることがあります。
ただし通常の履歴には出てこないので、「グラフに残らない」という理解で困ることはありません。

このサイトの `stash` は、本物より少しだけ大づかみです。2 点あります。

| 何が | このサイト | 本物 |
| --- | --- | --- |
| Git が知らないファイル（untracked） | 一緒に退避する | **置いていく**。持っていくには `-u` が要る |
| `pop` したとき | ステージに載せていたものは、載ったまま戻る | **すべて未ステージで戻る**。載せ直すには `add` |

上のほうが実務では効きます。本物で「`stash` したから手元は空のはず」と思って枝を移ると、
新しく作ったファイルだけが付いてきて、移った先で一緒にコミットされる ― これはよく踏みます。
