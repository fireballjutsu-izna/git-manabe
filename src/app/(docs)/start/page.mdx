# はじめに

このサイトの Git は、**本物の Git を動かしているわけではありません**。
コミット・ブランチ・HEAD・ステージを、教育用に単純化したデータとして持ち、
コマンドを「状態 → 新しい状態」の計算として実行しています。

そうしている理由は 1 つで、**いちばん図で見たい操作ほど、ブラウザで動く本物の Git が苦手**だからです。
たとえば rebase・reflog・コンフリクトの解決は、
純 JavaScript 実装の isomorphic-git には入っていないか、途中で中断してしまいます。
このサイトはそこを見せたいので、エンジンを自分で書いています。

## 最初に打つ並び

```bash
git init                  # まだコミットが 1 つも無いリポジトリができる
touch hello.txt           # 作業ディレクトリに変更を作る（Git のコマンドではありません）
git add hello.txt         # 作業ディレクトリ → ステージ
git commit -m "はじめの一歩"  # ステージ → リポジトリ。ここで main が生まれる
```

`git init` の直後は、`main` という枝は**まだ存在しません**。
HEAD は「これから作られる `main`」を指していて、最初の `commit` がその枝を生みます。
本物の Git と同じ挙動なので、そのまま再現しています。

打ってみるなら[サンドボックス](/sandbox)へ。何をしても壊れません。

## どこから読むか

やりたいことに合わせて、入口が 3 つあります。

| 入口 | 向いている人 |
| --- | --- |
| [記事](/docs) | 仕組みを読んで納得したい人へ。1 本につき概念 1 つ、{DOCS.length} 本 |
| [レベル](/levels) | 手を動かして覚えたい人へ。状況はこちらで用意します。{LEVELS.length} 個 |
| [シナリオ](/scenarios) | 仕事として解きたい人へ。実務の 1 場面を一続きに。{SCENARIOS.length} 本 |
| [サンドボックス](/sandbox) | 自由に触りたい人へ。目標も判定もありません |

記事とレベルは同じ順に並んでいて、題も対応しています。
記事の末尾から同じ題のレベルへ、そのまま進めます。

**読むだけだと、たいてい身に付きません。**
どちらから入っても構いませんが、片方だけで終わらせないことをおすすめします。

## 3 つの領域だけ、先に

どの記事から読むにせよ、これだけは先に知っておくと楽です。
Git が値を持つ場所は 3 つあります。

| 領域 | 何が入っているか | 動かすコマンド |
| --- | --- | --- |
| 作業ディレクトリ | 編集しただけで、まだ Git に渡していない変更 | `touch` / `edit` |
| ステージ (index) | 次のコミットに含めると決めた変更 | `git add` |
| リポジトリ | コミットとして確定した履歴 | `git commit` |

コマンドを打つと、**書き換わった領域だけが一瞬光ります**。
どのコマンドがどこを触ったのかは、説明を読むより、それを見るのがいちばん早いです。

詳しくは[3 つの領域](/docs/areas)で。

## 本物との違い

- コミット ID は本物の SHA-1 ではなく、7 桁の見た目だけ似せた文字列です
- ここでの操作は、あなたの実際のリポジトリには一切影響しません
- ファイルの中身は**短い行の配列**として持ちます。1 行の中のどこが変わったか（文字単位の差分）や、
  バイナリファイルまでは踏み込んでいません
- `.gitignore` が読むのは `.env` / `*.key` / `secrets/` の 3 書式だけです
- rebase はマージコミットを置き直しません（本物の git も既定では落とします）
- リモートは同じブラウザの中の別の入れ物で、実際の通信はしていません

## Git には無いコマンド

このサイトだけの補助コマンドが {HELPER_COMMANDS.length} つあります。
本物を触るときには存在しないので、区別しておいてください。

| コマンド | 何をするか |
| --- | --- |
| `touch <path> [中身]` | ファイルを作る（エディタでの操作にあたります） |
| `edit <path> [中身]` | 1 行目を書き換える |
| `append <path> <行>` | 末尾に 1 行足す |
| `cat <path>` | 中身を読む（本物ではシェルの cat やエディタにあたります） |
| `todo …` | 対話的 rebase の計画を組み立てる（本物はエディタで書き換えます） |
| `teammate <数>` | 「同僚が向こうへコミットした」ことにする |

正確な仕様を知りたくなったら、[git-scm 公式ドキュメント](https://git-scm.com/doc)へどうぞ。
